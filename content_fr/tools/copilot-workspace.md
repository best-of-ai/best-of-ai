Copilot Workspace était la tentative de GitHub Next de repenser la place de l'IA dans la correction d'une issue. À partir d'une issue GitHub ou d'un prompt, il écrivait d'abord une spécification du comportement actuel et souhaité, puis un plan listant les fichiers à modifier, et enfin le code. À chaque étape, tu pouvais modifier le texte, donc tu orientais le travail en langage clair avant qu'aucun code n'apparaisse. Les changements finis pouvaient s'ouvrir en pull request ou tourner dans un environnement cloud.

C'était un aperçu technique plutôt qu'un produit fini, et ça montrait comment GitHub imaginait que des agents pourraient un jour traiter des tickets de routine. L'aperçu est terminé, et on ne peut plus créer ni ouvrir d'espaces de travail. GitHub a dit que les remplacements les plus proches sont le mode agent de Copilot dans VS Code et l'agent de code Copilot, qui prend une issue assignée et y travaille en arrière-plan, mais ce n'est pas un équivalent exact.

Si tu veux ce style de flux aujourd'hui, l'agent de code dans GitHub Copilot est l'option la plus proche, avec des outils comme Devin, OpenAI Codex, Google Jules et Claude Code. Ceux-là traitent les tâches de bout en bout, en renvoyant en général une pull request à relire. L'étape spécification puis plan, qui rendait Workspace distinctif, apparaît maintenant dans d'autres outils comme des modes de planification. Cette fiche reste pour référence, puisque des liens, des articles et des pages d'alternatives parlent encore de lui.
