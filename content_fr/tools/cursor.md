Cursor a commencé comme un fork de Visual Studio Code, donc l'interface, les extensions et les raccourcis sont familiers à qui a utilisé VS Code. La différence, c'est que l'IA fait partie de l'éditeur plutôt que d'un ajout. Il prédit ta prochaine modification, pas seulement le prochain token, donc un renommage ou un changement répété peut souvent s'appliquer d'une seule tabulation. Tu peux aussi sélectionner du code et demander une réécriture, ou discuter avec un modèle qui a indexé tout le dépôt et peut répondre à des questions sur des fichiers que tu n'as pas ouverts.

Son mode agent, c'est ce que la plupart des gens entendent quand ils parlent de Cursor. Face à une tâche comme ajouter une page de réglages ou corriger un test qui échoue, l'agent planifie les étapes, modifie des fichiers dans le projet, lance des commandes, lit les erreurs et réessaie. Tu relis les changements en diffs avant de les accepter. Des fichiers de règles permettent d'écrire les conventions du projet pour que l'agent les suive, et des agents en arrière-plan peuvent travailler sur une tâche dans le cloud pendant que tu fais autre chose. Cursor laisse choisir entre des modèles de plusieurs fournisseurs, et propose aussi ses propres modèles.

Cursor a une offre gratuite avec un usage limité et des offres payantes pour les particuliers, les équipes et les entreprises. Un usage intensif de l'agent peut épuiser le quota inclus, donc les coûts dépendent de ta façon de travailler et des modèles choisis. Comme c'est une application à part, l'utiliser veut dire changer d'éditeur, même si tes réglages et extensions VS Code peuvent être importés. Les équipes avec des exigences strictes de confidentialité devraient lire les options de traitement des données, puisque le code est envoyé aux fournisseurs de modèles sauf si un mode privé est activé. Les alternatives incluent GitHub Copilot dans VS Code, Windsurf et Claude Code.
