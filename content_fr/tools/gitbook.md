GitBook aide les équipes à publier une documentation que les gens peuvent vraiment parcourir. Les rédacteurs utilisent un éditeur clair pour créer des pages, les ranger dans des espaces et des collections, et les publier comme un site de documentation soigné, avec recherche, navigation et versions. Les éditeurs de logiciels s'en servent pour la doc produit, les références d'API et les bases de connaissances internes, et le même contenu peut être public ou limité aux équipes.

Les fonctions pensées pour les développeurs font la différence. Le contenu peut se synchroniser avec un dépôt GitHub ou GitLab, donc la doc peut vivre à côté du code et passer par des pull requests, et un flux de demande de modification permet de relire les éditions avant publication. Les imports OpenAPI génèrent des pages de référence d'API, et les intégrations relient analytics, outils de support et chat. Côté IA, un assistant répond aux questions des lecteurs à partir de la doc, la recherche est enrichie, et l'écriture et l'édition des pages sont aidées.

GitBook a une offre gratuite pour les particuliers et les projets open source, et des offres payantes pour les équipes, avec domaines personnalisés, permissions avancées et analytics. C'est plus simple à mettre en place que de construire un site de doc avec un générateur de site statique, mais la liberté de design est moindre. Les alternatives incluent Mintlify, centré sur la doc développeur avec de vraies fonctions d'IA, ReadMe pour la documentation d'API, Docusaurus pour l'auto-hébergement open source, et Confluence ou Notion pour les wikis internes.
