// criterios del ranking

El uso importa, pero el ranking no es una simple clasificación por popularidad. Una buena herramienta con poca audiencia puede estar en la lista. Una viral que no funciona, probablemente no. Decidimos según si la herramienta cumple lo que promete para quienes la usan.

// qué se elimina

Quitamos herramientas que han dejado de funcionar, proyectos parados sin actividad durante mucho tiempo, productos que se lanzaron con etiqueta de IA pero nunca entregaron nada y clones sin una base real de usuarios.

// qué pasa después
Reporte publicado

Tu reporte entra en la cola de issues de GitHub. Puedes seguirlo allí y añadir más contexto si hace falta.

Los responsables lo revisan

Los reportes se revisan por tandas, normalmente en unos pocos días. Si necesitan más información, comentarán en el issue.

El cambio se publica

Los cambios aceptados se publican tras el siguiente despliegue. El issue se cierra con una nota sobre lo que cambió.

// ¿prefieres un pull request?
