Copilot Workspace fue el intento de GitHub Next de replantear cómo encaja la IA en el trabajo de resolver un issue. A partir de un issue de GitHub o de un prompt, primero escribía una especificación del comportamiento actual y del deseado, después un plan con los archivos que había que cambiar y, por último, el código. En cada fase se podía editar el texto, de modo que dirigías el trabajo en lenguaje llano antes de que apareciera código. Los cambios terminados podían abrirse como pull request o ejecutarse en un entorno en la nube.

Era una vista previa técnica y no un producto acabado, y mostró cómo pensaba GitHub que los agentes podrían encargarse algún día de los tickets rutinarios. La vista previa ha terminado y los usuarios ya no pueden crear ni abrir espacios de trabajo. GitHub ha dicho que los sustitutos más cercanos son el modo agente de Copilot en VS Code y el agente de programación de Copilot, que toma un issue asignado y trabaja en él en segundo plano, aunque no son equivalentes uno a uno.

Si hoy quieres un flujo de trabajo de este tipo, el agente de programación de GitHub Copilot es la opción más cercana, junto con herramientas como Devin, OpenAI Codex, Google Jules y Claude Code. Esas resuelven las tareas de principio a fin y suelen devolver un pull request para revisar. El paso de especificación y plan que hacía distinto a Workspace aparece ahora en otras herramientas como modos de planificación. Esta ficha se mantiene como referencia, porque enlaces, artículos y páginas de alternativas todavía se refieren a ella.
