Postman nació como una forma sencilla de enviar solicitudes HTTP sin escribir código, y sigue siendo la herramienta más habitual para probar una API. Escribes una URL, eliges un método, añades cabeceras y un cuerpo, y ves la respuesta. Las solicitudes se guardan en colecciones que se pueden compartir con el equipo, y los entornos permiten cambiar variables como las URL base y las claves entre desarrollo, preproducción y producción sin editar cada solicitud.

A partir de ahí se extiende al resto del ciclo de vida de la API. Puedes escribir scripts de prueba en JavaScript que comprueban las respuestas, ejecutar colecciones enteras en CI y programar monitores que vigilan la disponibilidad de un endpoint. Los servidores simulados devuelven respuestas falsas antes de que exista la API real, y la documentación se genera a partir de tus colecciones y se publica para otros desarrolladores. Los espacios de trabajo dan a los equipos un lugar único para sus API, y una red de API permite a las empresas publicar sus colecciones de forma pública. El asistente de IA puede escribir pruebas, explicar respuestas y ayudar a crear o depurar solicitudes, y Postman también admite probar agentes de IA y endpoints de servidores MCP.

Hay un plan gratuito, y los planes de pago añaden funciones de equipo, más uso y controles de administración. Una queja habitual es que Postman se ha vuelto más pesado con el tiempo y exige iniciar sesión, con los datos sincronizados en su nube por defecto. Los desarrolladores que quieren algo más ligero o que funcione en local suelen pasarse a Bruno, Insomnia o Hoppscotch, y otros prefieren curl o una extensión del editor. Para equipos que necesitan colecciones compartidas, pruebas y documentación en un solo sitio, Postman sigue siendo la opción por defecto.
